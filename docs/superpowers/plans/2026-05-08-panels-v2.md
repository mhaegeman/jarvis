# Panels v2 — Implementation Plan

> **For agentic workers:** This plan uses three execution modes: orchestrator inline (Phase A, B, D), parallel subagent dispatch (Phase C). Read `subagent-driven-development.md` before Phase C.

**Goal:** Replace placeholder values on all 9 HUD panels with real, live data from a new `state.snapshot` server message + `calendar.update` + ping/pong RTT.

**Architecture:** Server emits a 1 Hz JSON snapshot covering system / memory / network / tasks. A separate `calendar.update` fires on connect and every 30 min. Frontend `WSEventSource` decodes both into a new `panelData` store slice; each panel reads from it.

**Tech Stack:** Python 3.12, FastAPI, asyncio, psutil, google-auth + google-api-python-client; TypeScript 5, Vite, Vitest. No new frontend dependencies.

**Spec:** `docs/superpowers/specs/2026-05-08-panels-v2-design.md`

## Phase C — Per-panel subagent dispatch (parallel)

For each task C1–C9 the orchestrator dispatches an implementer subagent with a sealed prompt (template below), then a spec-compliance reviewer subagent, then a code-quality reviewer subagent — per `subagent-driven-development.md`.

Implementers run in parallel batches of 3 (disjoint files; spec §7 states the safety guarantee). Reviewers run sequentially per panel after that panel's implementer reports.
